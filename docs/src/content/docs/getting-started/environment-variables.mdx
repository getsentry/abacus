## Required Variables

These variables are required for Abacus to function:

| Variable | Description |
|----------|-------------|
| `POSTGRES_URL` | PostgreSQL connection string |
| `BETTER_AUTH_SECRET` | Secret for session encryption. Generate with: `openssl rand -base64 32` |
| `GOOGLE_CLIENT_ID` | Google OAuth client ID |
| `GOOGLE_CLIENT_SECRET` | Google OAuth client secret |
| `NEXT_PUBLIC_DOMAIN` | Email domain to restrict access (e.g., `sentry.io`) |
| `CRON_SECRET` | Secret for authenticating cron job requests. Generate with: `openssl rand -hex 32` |
| `OAUTH_PROXY_SECRET` | Shared secret for the OAuth proxy that enables Google login on Vercel preview deployments. Must be the **same value** in the Production and Preview environments (unlike `BETTER_AUTH_SECRET`, which should differ per environment). Not needed locally — register `http://localhost:3000/api/auth/callback/google` on the Google OAuth client and localhost logs in directly. Generate with: `openssl rand -hex 32` |

## Provider Variables

### Claude Code (Anthropic)

| Variable | Description |
|----------|-------------|
| `ANTHROPIC_ADMIN_KEY` | Anthropic Admin API key (starts with `sk-admin-`) |
| `ANTHROPIC_ADMIN_KEYS` | JSON array of keys for multiple organizations (see [Multi-Organization Keys](#multi-organization-keys)) |

See [Claude Code setup](/abacus/providers/claude-code/) for details.

### Cursor

| Variable | Description |
|----------|-------------|
| `CURSOR_ADMIN_KEY` | Cursor Admin API key |
| `CURSOR_ADMIN_KEYS` | JSON array of keys for multiple teams (see [Multi-Organization Keys](#multi-organization-keys)) |

See [Cursor setup](/abacus/providers/cursor/) for details.

### OpenRouter

| Variable | Description |
|----------|-------------|
| `OPENROUTER_MANAGEMENT_KEY` | OpenRouter Management API key (starts with `sk-or-v1-`). Single-workspace setup → workspace named `default`. Powers key provisioning and usage sync. |
| `OPENROUTER_MANAGEMENT_KEYS` | JSON map of workspace name → management key for tracking multiple OpenRouter workspaces. Takes precedence over `OPENROUTER_MANAGEMENT_KEY` when both are set. |

Example for multiple workspaces:

```bash
OPENROUTER_MANAGEMENT_KEYS='{"Coding Agents":"sk-or-v1-...","Tools":"sk-or-v1-..."}'
```

See [OpenRouter multi-workspace setup](/abacus/providers/openrouter/#multi-workspace-configuration) for details.

### GitHub Commits

| Variable | Description |
|----------|-------------|
| `GITHUB_APP_ID` | GitHub App ID |
| `GITHUB_APP_PRIVATE_KEY` | GitHub App private key (full PEM content) |
| `GITHUB_APP_INSTALLATION_ID` | Installation ID for your organization |
| `GITHUB_WEBHOOK_SECRET` | Webhook secret for verifying requests |

For local development only:

| Variable | Description |
|----------|-------------|
| `GITHUB_TOKEN` | Fine-grained personal access token (alternative to App) |

See [GitHub Commits setup](/abacus/providers/github-commits/) for details.

### Google Directory (Offboarding)

| Variable | Description |
|----------|-------------|
| `GOOGLE_SA_KEY_JSON` | Base64-encoded service account key JSON from GCP Console. Required for the nightly offboarding cron that auto-disables keys of suspended/deleted Workspace users. The service account must have domain-wide delegation with scope `https://www.googleapis.com/auth/admin.directory.user.readonly`. |
| `GOOGLE_DIRECTORY_SUBJECT` | Email address of a Google Workspace admin to impersonate via domain-wide delegation. The service account acts as this user when querying the Directory API. |

| Variable | Description |
|----------|-------------|
| `AUTH_BYPASS_LOCAL` | Set to `true` to bypass SSO login locally. Returns a mock "Dev User" session. |

<Aside type="tip">
  In Vercel, you can paste multi-line values (like the GitHub private key) directly. The newlines will be preserved.
</Aside>

## Multi-Organization Keys

For managing multiple Anthropic organizations or Cursor teams, use a JSON array:

```bash
ANTHROPIC_ADMIN_KEYS='[{"key":"sk-admin-xxx","name":"Engineering"},{"key":"sk-admin-yyy","name":"Research"}]'
CURSOR_ADMIN_KEYS='[{"key":"cur_xxx","name":"Team Alpha"},{"key":"cur_yyy","name":"Team Beta"}]'
```

Each entry requires:
- `key`: The admin API key
- `name`: A label identifying the organization or team (used in reports)

<Aside type="note">
  When both single-key (`*_ADMIN_KEY`) and multi-key (`*_ADMIN_KEYS`) variables are set, the multi-key variable takes precedence.
</Aside>
